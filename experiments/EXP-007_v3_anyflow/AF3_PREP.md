# AF3 8NFE continuation — CPU preparation only

The [AF3 runner](run_af3.py) and [configuration](config_v3_af3.json) prepare the matched 8NFE evaluation defined in [EXP-007/v3](taskbook_v3.md). **No AF3 GPU call has been made and no checkpoint/video claim is implied by this file.** Current `--preflight` correctly reports `WAITING_FOR_AF2_CHECKPOINT` while AF2 trains; source and checkpoint hashes can be frozen only after AF2 finishes.

After the AF2 final checkpoint is accepted, the CPU preflight checks paired QKV/target/optimizer metadata and hashes, the immutable EXP-006 FM8 first12 latent and 39 RGB frames, A/D input noise equality, and the identical native 8-step sigma grid. The GPU entrance also requires a Judge-created `AF3_GPU_AUTHORIZATION.json` containing `approved: true` and the exact selected `checkpoint_step`. AF3 has its own 35-forward/4-VAE/0.35-GPUh ledger and does not reuse AF2's GPU budget.

The planned stage order is shared C1 clean prefill (1 forward), AA/AD C2 sampling and clean commits (18 forwards, 2 decodes), then AA/AD C3 sampling (16 forwards, 2 decodes). Each finite map uses the next native sigma as target. C2 paths begin from the same EXP-006 FM8 first12 latent and their own student cache; C3 paths use their own AF-generated C2 history. Previously published RGB is appended immutably. Every stage verifies its parent chunk's status, checkpoint identity, and cache/endpoint SHA before loading. Every stage will get a separate full-frame contact sheet and raw video. The first 39 frames are borrowed from FM8, so this can only be called **AF continuation**, not end-to-end AF from the first chunk.
