## Frozen conditional GPU protocol

Reuse the v5 isolated FlashAttention overlay and the independently patched four-card CPU-to-FSDP loading source, not the official unpatched whole-model `.to(cuda)` path. Use SP4/DP1 on four free L40s, one seed-42 case, `checkpoint.weight_source=ema` from `SolarWM-h3-33B-sgf-stage2-158f-fix`, native camera/time conditioning, Single I0 from the encoded anchor, `student_rope_mode=sliding_local`, 5-latent chunks, six-chunk local KV window, 50 generated latents / first 47 decoded, 158 RGB frames at 1344×768 and 24 fps. `validation.num_inference_steps=4` in the official Stage2 `generate()` means **four student denoiser forwards per chunk**, not four forwards total. Ten 5-latent chunks imply **40 denoiser forwards plus 10 clean KV-commit forwards = 50 logical model forwards** (200 rank-local invocations over SP4). The inference path does not call the training replay or critic. It loads the video VAE on the SP writer after generation and, with reference latents present, decodes generated and reference latents; these two codec decodes and initial model load must be included in wall time and peak memory. The older candidate YAML's `validation.passes: [live, ema]` is a training-validation field; `run_inference()` instead loads only `checkpoint.weight_source=ema` and emits one inference result. Remove the misleading extra-pass list in any final reviewed config.
