# Conditional load-only GPU check (future authorization required)

EXP-026/v2 permits **zero GPU initialization, forwards and downloads**. This document is a budget request for Judge review, not permission to execute. The current patch and candidate are only CPU checked.

Use the official eight-rank SP4/DP2 topology, with the existing physical-node eight-way frozen-base HYBRID_SHARD option. The two-case candidate preserves Stage2's `balance_by_dataset=true`, camera/condition protocol, four-NFE sampler, 158-frame output, and published EMA. Its sample IDs remain unknown; a load-only gate can stop before reader construction and does not require fabricated inputs. A full inference gate later requires the authentic index, two selected rows, support files and payload shards, followed by CPU reader validation.

Before any eight-rank attempt, require all eight L40s to be actually idle, within the permitted night window, and verify at least **650 GiB MemAvailable** immediately before launch. The 650 GiB threshold is a conservative proposed stop rule, not a measured peak: the eight loaded base-plus-LoRA replicas alone have a 524.75 GiB arithmetic lower bound. At the v2 audit, MemAvailable was 546.53 GiB and GPUs 2–5 were occupied, so the gate currently fails. The OS and other users' processes may change this state. Do not use swap as capacity.

Proposed first authorization: **one load-only attempt, at most 8 GPUs × 600 seconds = 4,800 GPU-seconds**, no denoising/codec forward, no checkpoint updates, no video. Run a separate reviewed entry that initializes NCCL, strict-loads the frozen 33B base onto CPU on each rank, injects the released LoRA, wraps it through the existing eight-way frozen-base group, loads the Stage2-fix EMA into only LoRA, then reports per-rank CPU RSS and CUDA allocated/reserved. The entry must end before official reader or sampler. Stop all ranks on any host-memory pressure, swap growth, FSDP collective mismatch, single-rank allocated >40 GiB, nonfinite/incorrect adapter descriptors, or 600-second wall limit. A staged startup or more memory-efficient source-weight streaming may be required; neither is implemented or claimed here.

The critical untested question is whether CPU-initialized per-block FSDP with ignored GPU LoRA parameters can wrap and synchronize correctly across SP groups while staying under L40 peak memory. The production code uses this eight-way physical sharding in its Stage2 training configuration, but this exact inference startup path and its transient allocations have not been tested. If the load-only check fails, diagnose loading/partitioning rather than treating the result as a video-quality failure. Full two-sample 158-frame inference needs a **separate** authorization and data access after load-only success.
